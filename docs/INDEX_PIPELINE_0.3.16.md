# Accelerated indexing pipeline — 0.3.16-alpha

Индексатор переведён на ограниченный конвейер подготовки и пакетной обработки:

- чтение, хеширование и извлечение содержимого выполняются несколькими CPU-потоками;
- текстовые фрагменты разных файлов объединяются в общие пакеты модели;
- изображения разных файлов объединяются в общие Vision-пакеты;
- изменения файлов записываются в SQLite одной транзакцией на группу;
- вставка фрагментов и FTS-записей выполняется пакетно;
- таблица ранее индексированных файлов предварительно загружается в память;
- SQLite использует WAL, `synchronous=NORMAL`, 64 МБ кеша и временные данные в памяти;
- пауза, отмена, кеширование фрагментов и продолжение незавершённой индексации сохранены.

## Настройки

- **Потоки индексации:** 2, 4, 8, 16 или 32; по умолчанию 8.
- **Размер пакета эмбеддингов:** 32, 64, 128, 256 или 512; по умолчанию 128.
- **Очередь подготовки:** 16, 32, 64, 128, 256 или 512 файлов; по умолчанию 64.

Число потоков влияет на CPU, дисковую нагрузку и RAM. Размер пакета в первую очередь влияет на VRAM. Очередь подготовки ограничивает объём заранее извлечённых данных в оперативной памяти.

Параметр «Количество результатов» задаёт только максимальное число файлов в выдаче и не влияет на индексацию.
